# Конфигурация Kafka кластера

1. SaslMechanism

SASL механизм аутентификации: GSSAPI, PLAIN, SCRAM-SHA-256,
SCRAM-SHA-512

2. Acks

Количество подтверждений, который лидер должен получить от ICR (In Sync Replicas) брокеров прежде чем ответить на запрос

0 - брокер не посылает никаких ответов/подтверждений клиенту
1 - лидер запишет запись в локальный лог, но ответит не дожидаясь полного подтвеждения от каждой реплики
all - брокер заблокирован пока сообщение фиксируется всеми ICR

3. ClientId

4. BootstrapServers

5. MessageMaxBytes

6. MessageCopyMaxBytes

Максимальный размер  сообщения, способное скопироваться в буффер

7. ReceiveMessageMaxBytes

8. MaxInFlight

Максимальное количество запросов "в полете" за одно подключение к брокеру.

9. topic.metadata.refresh.interval.ms

Период времени в миллисекундах, в течение которого метаданные темы и брокера обновляются, чтобы заблаговременно обнаруживать любые новые брокеры, темы, разделы или изменения лидера раздела.

10. MetadataMaxAgeMs

Максимальный возраст метаданных кэша. По умолчанию: topic.metadata.refresh.interval.ms * 3

11. topic.metadata.refresh.fast.interval.ms

Когда топик теряет своего лидера новый запрос метданных будет поставлен в очередь незамедлительно и с этим интервалом экспоненциально возрастает до retry.backoff.max.ms, до тех пор пока метаданные не будут обновлены.

Это значение не задается явно, оно по умолчанию задается retry.backoff.ms

12. topic.metadata.refresh.sparse (bool)

Разреженные запросы метаданных

13. topic.metadata.propagation.max.ms (int)

Топик создается асинхронно и это занимает время чтобы новый топик распространился через кластер ко всем брокерам. Если клиент запросит метаданные топика после его ручного создания, но до того, как топик полностью распространится по брокеру, клиент запрашивающий метаданные топика, получит ERR__UNKNOW__TOPIC при продюсировании сообщения.

Эта настройка откладывает пометку топика как несуществующего до тех пор, пока не пройдет максимальное время распространения. Максимум времени распространения вычисляется со времени когда топик впервые упоминается клиентом, т.е. produce. default: 30000

14. topic.blacklist (string)

Список регулярных выражения через запятую для соответствия названиями топиков которые должны игнорировать в метаданных брокера, как топики, которые не существуют

15. debug (string)

Разделенный через запятую список контекстов для включения. 

Подробная отладка продюсера: broker, topic, msg. Консюмер: consumer, cgrp, topic, fetch

16. SocketTimeoutMs

Дефолтный таймаут для сетевых запросов. 

Producer: ProduceRequests будет использовать меньшее значение из `socket.timeout.ms` и `message.timeout.ms` для первого сообщения из партии

Consumer: ConsumeRequests будет использовать `fetch.wait.max.ms` + `socket.timeout.ms`

Admin: Запросы админа будут использовать socket.timeout.ms` или явно заданный `rd_kafka_AdminOptions_set_operation_timeout()` значение.

17. socket.send.buffer.bytes

Размер буффера, который отправляет сокет брокера

18. SocketReceiveBufferBytes

Размер буффера, который получает сокет брокера

19. SocketKeepaliveEnable (bool)

Включение TCP пВключить проверку активности TCP (SO_KEEPALIVE) в сокетах брокера.

20. socket.nagle.disable (bool) default: false

Выключить Nagle алгоритм (TCP_NODELAY) на сокетах брокера.

**Алгоритм Nagle** — это механизм, разработанный для уменьшения количества маленьких пакетов данных, передаваемых по сети. Его цель — объединение нескольких маленьких сообщений в один большой пакет перед отправкой, что помогает улучшить общую эффективность сети и уменьшить накладные расходы.

21. socket.max.fails (int) default 1

Отключение от брокера, когда это число отправок заканчивается неудачей (т.е. таймаут запросы).

22. broker.address.ttl (int): default: 1000

Как долго кэшировать результататы разрешения адреса брокера

23. broker.address.family, default: any

Позволенную брокеру семейства IP адресов: any, v4, v6

24. socket.connection.setup.timeout.ms, default: 30000

Максимальное время позволенное брокеру настраивать соединение (TCP соединение включается также SSL и SASL рукопожатие)

25. connections.max.idle.ms, default 0

Закрывает соединения брокера после заданного времени неактивности. 

26. reconnect.backoff.ms, default: 100

Начальное время ожидание прежде чем переподлючиться к брокеру после того, как соединения закрылось

27. reconnect.backoff.max.ms, default: 1000

Максимальное время ожидание после переподлюкчения к брокеру после того, как подключение закрылось

28. statistics.interval.ms, default 0

librdkafka статистика выдает интервал. Приложение также доолжно регистрировать кэллбэк статичесики используются `rd_kafka_conf_set_stats_cb()`. Детализация - 1000 ms.

29. log.queue, default: false

Отключить спонтанный log_cb из внутренних потоков librdkafka, вместо  этого ставить в очередь записанные сообщения, установленную с помощью `rd_kafka_set_log_queue()` и обслуживаем обратные вызовы журнала или события через стандартные API опроса

30. log.thread.name, default: true

Печатает внутреннее имя потока в сообщениях лога

31. enable.random.seed, default: true



# Конфигурация producer

1. delivery.report.background.thread (bool)

Управление фоновыми потоками, которые обрабатывают отчеты о доставке.
Продюсер kafka может использовать фоновый поток для обработки доставки сообщений и получения уведомлений о статусе сообщения. Это позволяет основному потоку выполнять другие задачи, не блокируясь на получение этих сообщений.
Отчет о доставке - продюсер может предоставлять уведомления о том, было ли сообщение успешно доставлено или произошла ошибка. Эти уведомления могут быть получены асинхронно через фоновый поток.

2. producer.enable.delivery.reports (bool)

Будут ли приходить сообщения отчетов о доставке

3. producer.delivery.report.fields (string)

Поля которые могут быть настроены для отчетах о доставке. Их настройка может помочь настроить пропускную способность и уменьшить использование памяти. Значения: key, value, timestamp, headers, status, all, none. Default - all

4. request.required.acks (int)

Тайм-аут подтверждение запроса продюсера в миллисекундах. Это знчение применяется только брокером. default: 30000

5. message.timeout.ms (int)

Локальный тайм-аут сообщений. Это значение применяется только локально и ограничивает время, сколько сообщение ждет успешной отправки. Это значение автоматически корректируется значением 
`transaction.timeout.ms` если transactional.id сконфигурировано

6. Partitioner

Различные стратегии распределения сообщений по партициям в топике.

Random, Consistent, ConsistentRandom, Murmur2, Murmur2Random

7. CompressionLevel (int)

Алгоритм, выбранный при конфигурировании поля compression.codec
Чем больше значение, тем лучше компрессия за счет большего CPU использования. gzip, lz4, snappy

8. TransactionalId (int)

**transactional producer** - механизм, который обеспечивает атомарность и целостность при отправке сообщений. Этот механизм позволяет отправлять группы сообщений как единое целое, гарантируя, что либо все сообщения в группе будут успешно доставлены, либо ни одно из них не будет доставлено. Это особенно важно для сценариев, где надежность и последовательность сообщений критичны, например, в финансовых транзакциях или при обработке критически важных данных.

Transactional.id используется для идентификации одного и того же экземпляра производителя транзакций при перезапуске процесса.
Это позволяет продюсера гарантировать что транзакции соответсвующие предыдущим экземлярам продюсера завершено ранее
Это позволяет производителю гарантировать, что транзакции, соответствующие более ранним экземплярам тот же производитель был завершен до начала каких-либо новых транзакций,и что любые экземпляры зомби огорожены
