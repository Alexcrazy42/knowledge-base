# Metaprogramming

## Создание объектов

Когда компилятор видит new Foo(), он генерирует примерно такой IL:

```txt
newobj instance void Foo::.ctor()
```

Инструкция newobj делает три вещи:

1. Выделяет память под объект в куче.
2. Копирует в начало объект-заголовок (method table pointer + sync block index).
3. Вызывает указанный конструктор с переданными аргументами.

Всё это делает JIT-компилятор, когда превращает IL в машинный код. Он уже знает, что такое Foo, поэтому генерирует прямой вызов конструктора — максимально быстро.

А теперь ключевой вопрос: как сделать то же самое, когда Type известен только в рантайме? Это и есть предмет нашего изучения

## Вызов метода (MethodInfo, Invoke)

Когда компилятор видит obj.Method(arg), он генерирует IL-инструкцию callvirt (для экземплярных методов) или call (для статических). JIT-компилятор превращает ее в прямой вызов по адресу метода. Это максимально быстро - примерно 1-2 наносекунды.

Проблема в том, что при использовании рефлексии (MethodInfo.Invoke) этот прямой путь недоступен. Вместо него CLR выполняет целую цепочку действий, которую можно назвать "медленным путем"

🐢 Что делает MethodInfo.Invoke «под капотом»

Метод Invoke принимает два аргумента: целевой объект (или null для статических методов) и массив object[] с аргументами. Вот что происходит внутри:

1. Проверка аргументов: CLR убеждается, что количество и типы переданных аргументов соответствуют сигнатуре метода.
2. Упаковка (Boxing): Если метод принимает значимые типы (int, decimal, bool и т.д.), они должны быть помещены в object[]. Это требует выделения памяти в куче (boxing), что является дорогой операцией.
3. Поиск метода: MethodInfo уже содержит метаданные, поэтому поиск не такой медленный, как Type.GetMethod(), но всё равно требуется проверка.
4. Непосредственно вызов: CLR выполняет вызов целевого метода с распакованными аргументами.
5. Распаковка результата: Возвращаемое значение (если это значимый тип) снова упаковывается в object, чтобы соответствовать сигнатуре Invoke.

Именно эти накладные расходы (boxing, проверки, отсутствие инлайнинга) делают MethodInfo.Invoke в 10–100 раз медленнее прямого вызова

### Получение аттрибутов

Цель: навешанные аттрибуты как декларативные инструкции для генерации поведения (Retry). GetCustomAttribute

Аттрибут - только данные в метаданных сборки. Компилятор встраивает его как запись в таблицу CustomAttribute в PE-файле (dll или exe). В рантайме эти данные можно прочитать через GetCustomAttribute<T>() — и всё.

Чтобы атрибут «ожил», нужен второй участник — «драйвер» (invoker, прокси, interceptor, source generator), который:

1. Прочитает атрибут.
2. Извлечёт из него параметры.
3. Сгенерирует поведение на основе этих параметров.
