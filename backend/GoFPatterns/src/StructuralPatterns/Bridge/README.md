# Мост

Структурный паттерн, который разделяет абстракцию и реализацию, позволяя
им изменяться независимо. Он использует композицию вместо наследования,
чтобы абстракция (например, графический интфрейс) могла работать с разными
реализациями (например, разными графическими API)

Проблемы, котораы решает:
Жесткая связь между абстракцией и реализацией
Если абстракция и реализация связаны через наследование, то изменение
одной части требует модификации другой
Пример: добавление поддержки нового графического движка (Vulkan) в
класс Window приведет к взрывному росту подклассов
(VulkanWindow, DirectXWindow и т. д.).

Сложность масштабирования
Наследование создает глубокие иерархии классов, которые трудно поддерживать.

Необходимость поддержки нескольких платформ/API
Например, графическое приложение должно работать с OpenGL, DirectX и
другими API, но без дублирования кода.


Где применяется в .NET:

Хотя явных примеров "Моста" в стандартной библиотеке .NET мало
(так как он чаще используется в сложных GUI-фреймворках), его концепция прослеживается в:

1. System.Drawing и Graphics
   Абстракция: Graphics (рисование фигур, текста).

Реализация: GdiGraphics (для Windows), CairoGraphics (для Linux через Mono).

2. DbConnection и драйверы БД
   Абстракция: DbConnection (общий интерфейс для работы с БД).

Реализация: SqlConnection, MySqlConnection и др.

3. Stream и его наследники
   Абстракция: Stream (чтение/запись байтов).

Реализация: FileStream, MemoryStream, NetworkStream.
