# Интерпретатор

Проблемы, которые решает:
1. обработка доменно-специфичных языков (DSL) - например: SQL, математические формулы, правила валидации
2. разделение грамматики и логики - позволяет изолировать правила языка от кода, который их исполняет
3. гибкость - упрощает добавления новых правил без изменения существующего кода

Примеры:
1. Регулярные выражения (a|b*).
2. Арифметические выражения (5 * (3 + 2)).
3. Простые SQL-условия (WHERE name = 'Alice').
4. Конфигурационные файлы (JSON, YAML — но уже на грани).

Не подходит для:
1. Языки программирования (Python, C#).
2. SQL целиком (SELECT, JOIN, подзапросы).
3. Шаблоны C++/Rust.
4. Естественные языки (английский, русский).


Что использовать вместо интерпретатора?
Если грамматика сложная:
1. Парсер-комбинаторы (библиотеки типа Sprache для C#).
2. Генераторы парсеров (ANTLR, Yacc, Bison).
3. Visitor для обхода AST.

Строка -> AST
Библиотеки, которые упрощают написание парсеров. (Sprache, Superpower)
Генераторы парсеров (ANTLR, Yacc)
Для сложных грамматик (SQL, языки программирования).
ANTLR генерирует парсер на основе описания грамматики в .g4-файле.
Выходные данные — готовые классы на C#/Java/Python.

Парсинг строки → разбиваем на токены.
Построение AST → рекурсивно создаём объекты выражений.
Интерпретация → обходим дерево и выполняем код.

# Примеры из .NET:

Регулярные выражения (System.Text.RegularExpressions)

Как применяется:
Регулярные выражения (Regex) — это типичный пример интерпретатора.
Грамматика: Паттерны типа a|b* описывают язык для поиска строк.
AST: .NET компилирует regex в дерево операций (например, RegexNode во внутренней реализации).
Интерпретация: Движок regex рекурсивно обходит дерево для поиска совпадений.


LINQ Query Expressions

LINQ-запросы (where, select) преобразуются в AST, который затем интерпретируется или компилируется.
Грамматика: Запросы вида from x in collection where x > 0 select x.
AST: Выражения (Expression<T>) представляют дерево операций.
Интерпретация: LINQ to Objects выполняет запрос в памяти; LINQ to SQL транслирует в SQL.

```csharp
var query = from num in numbers
            where num % 2 == 0
            select num * 2;
// За кулисами: строится Expression Tree, затем интерпретация/компиляция
```


Dynamic LINQ (System.Linq.Dynamic)
Как применяется:
Позволяет строить LINQ-запросы из строк, используя парсер выражений.
Грамматика: Строки типа "Age > 18 && Name.Contains('A')".
AST: Разбирается в System.Linq.Expressions.
Интерпретация: Динамически создаётся лямбда-выражение.

```csharp
var result = data.AsQueryable().Where("Age > 18");
```

XPath (System.Xml.XPath)
XPath-запросы (/book/title) интерпретируются для поиска в XML.
Грамматика: Пути типа //element[@attr='value'].
AST: Внутреннее дерево разбора XPath.
Интерпретация: Обход XML-документа по правилам запроса.

```csharp
var nav = doc.CreateNavigator();
var nodes = nav.Select("/books/book[price > 10]"); // Интерпретация XPath
```

ASP.NET Core Routing
Шаблоны маршрутов (/users/{id}) разбираются и сопоставляются с URL.

Грамматика: Правила типа "api/{controller}/{action}/{id?}".
AST: Внутреннее представление шаблона (например, RoutePattern).
Интерпретация: Проверка входящих URL на соответствие шаблону.

```csharp
app.MapGet("/users/{id}", (int id) => GetUser(id));
```

Конфигурация (IConfiguration)
Как применяется:
Ключи конфигурации (Logging:LogLevel:Default) разбираются как иерархия.
Грамматика: Разделители : для вложенных секций.
AST: Внутреннее дерево конфигурационных узлов.
Интерпретация: Рекурсивный поиск значения по ключу.

```csharp
var level = Configuration["Logging:LogLevel:Default"];
```

Entity Framework Core (LINQ to SQL)
Как применяется:
LINQ-запросы преобразуются в SQL через разбор AST.
Грамматика: C# LINQ-методы (Where(), OrderBy()).
AST: IQueryable и Expression<T>.
Интерпретация: Трансляция в SQL (например, SELECT * FROM Users WHERE Age > 18).

```csharp
db.Users.Where(u => u.Age > 18).ToList();
```

Roslyn (Компилятор C#)
Как применяется:
Разбор исходного кода C# в синтаксическое дерево (SyntaxTree).

Грамматика: Весь язык C#.
AST: SyntaxNode, SyntaxToken.
Интерпретация: Анализ кода, рефакторинги.

```csharp
var tree = CSharpSyntaxTree.ParseText("class C { void M() { } }");
var root = tree.GetRoot(); // Получение AST
```

Паттерн Интерпретатор в .NET используется везде, где нужно:
Разбирать структурированный текст (regex, XPath, LINQ).
Строить AST для последующего выполнения или трансляции.
Обрабатывать запросы/команды без жёсткой привязки к их представлению.
