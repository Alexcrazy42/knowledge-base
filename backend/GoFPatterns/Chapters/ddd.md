осведомленность - целое существует без части, целое и часть равны

композиция - жесткое владение, часть создается в целом и живет вместе с ним


1. Агрегация vs. Агрегаты (Aggregates) в DDD
   Агрегация в ООП
   Объект-часть может принадлежать нескольким целым.

Часть логически подчинена целому (например, Engine подчинён Car).

Часть не имеет смысла вне контекста целого (двигатель без машины бесполезен).

## Агрегат в DDD
Это кластер связанных объектов, где один корневой объект (Aggregate Root)
контролирует доступ к остальным.

Пример: Order (корень) содержит OrderItem (часть). Внешние системы работают
только с Order, а не с OrderItem напрямую.

Правила:
Части агрегата не могут быть изменены без участия корня.
Агрегат — граница транзакций и согласованности.

Сходство:
Оба подчёркивают логическое подчинение части целому, но в DDD агрегат — это
ещё и граница согласованности.


2. Осведомлённость vs. Объекты-значения (Value Objects)
   Осведомлённость в ООП
   Объекты равноправны (Teacher знает о School, но школа не его часть).

Часть (Color) может использоваться в разных контекстах.

Value Object в DDD
Не имеет идентификатора, определяется своими атрибутами (например, Color, Money).

Может свободно передаваться между агрегатами.

Непривязан к жизненному циклу другого объекта.

Сходство:
Value Objects часто участвуют в ассоциациях, так как они независимы и
многократно используемы.

3. Композиция vs. Сущности (Entities) внутри агрегатов
   Композиция в ООП
   Жёсткое владение: часть (Heart) создаётся и уничтожается вместе с целым (Human).

Сущность (Entity) в DDD внутри агрегата
Имеет идентификатор, но её жизненный цикл контролируется корнем агрегата.

Пример: OrderItem существует только внутри Order и удаляется с ним.

Сходство:
Композиция в ООП похожа на вложенные сущности в DDD, которые не могут
существовать без корня.


```csharp
// Value Object (DDD) / Осведомлённость (ООП)
public class Address
{
    public string Street { get; }
    public string City { get; }
}

// Entity (DDD) / Композиция (ООП)
public class OrderItem
{
    public Guid Id { get; }
    public int Quantity { get; }
}

// Aggregate Root (DDD) / Агрегация (ООП)
public class Order
{
    private List<OrderItem> _items = new();
    public Address DeliveryAddress { get; } // Value Object

    public void AddItem(OrderItem item) => _items.Add(item);
}
```



# DDD формализует эти понятия

Агрегация в ООП → Aggregate Root + Entities в DDD.

Осведомлённость в ООП → Value Objects в DDD.

Композиция в ООП → Сущности, жёстко связанные с агрегатом.
