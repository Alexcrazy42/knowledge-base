# Наиболее полезные паттерны

## Команда

определение, постаночка в очередь и выполнение запросов в разное время (брокер собщений)
поддердка отмены операций (Saga)
поддержка протоколирования изменений, чтобы их можно было выполнить повторно после сбоя в системе (Dead letter queue в кафке)

## Адаптер
Адаптирует старый интерфейс или другой интерфейс к тому, что нужно нам

## Фасад
Дает входную точку в сложную систему, упрощаяя ее

# Наблюдатель
Паттерн *наблюдатель* описывает, как устанавливаются такие отношения. Ключевыми объектами в нем
являются субъект и наблюдатель. У субъекта может быть сколько угодно завимимых от него наблюдателей.
Все наблюдатели уведомляются об изменениях в состоянии субъекта. Получив уведомление, наблюдатель
опрашивает субъекта, чтобы синхронизовать с ним свое состояние.

Такого рода взаимодействие часто называются отношением издатель-подписчик. Субъект издает или
публикует уведомления и рассылает их, даже не имея информации о том, какие объекты являются
подписчиками На получение уведомлений может подписать неограниченное количество наблюдаталей.

CQRS — для разделения чтения/записи.
Saga — для распределённых транзакций.
Repository/Unit of Work — для работы с данными.
Circuit Breaker/Retry — для устойчивости.
Event Sourcing — для аудита и восстановления состояния.
Pub/Sub — для асинхронной коммуникации.
API Gateway/BFF — для клиентских API.
MVVM — для UI-приложений.
Dependency Injection — для управления зависимостями.
Builder/Factory — для создания объектов.
