# Осведомленность vs Агрегация vs Композиция

Линия со стрелкой с ромбиком на конце - ссылка на объект, представляющая
отношение агрегирования "является частью"

[Car] ◇──> [Engine]
[Drawing] ◇──> [Shape]

Аггрегирование:

1.Отношение "has-a" ("имеет часть")
Пример: Автомобиль агрегирует Двигатель — двигатель является частью автомобиля,
но может существовать и отдельно
Часть может принадлежать другому целому - двигатель можно вынуть из Car1 и
вставить в Car2
Нет управления жизненным циклом - Car не удаляет Engine при своем уничтожении

2. Ссылка на объект-часть
В коде это выражается через поля-ссылки на другой объект, но без управления
его жизненным циклом.

3. Часть может принадлежать разным целым
В отличие от композиции, "часть" не уничтожается при удалении "целого".

```csharp
public class Engine { } // "Часть"

public class Car
{
    private Engine _engine; // Агрегация: Car имеет ссылку на Engine

    public Car(Engine engine)
    {
        _engine = engine; // Engine передаётся извне
    }
}

// Использование:
var engine = new Engine(); // Создаём "часть" отдельно
var car = new Car(engine); // Передаём в "целое"

// Даже если car уничтожится, engine продолжит существовать
// вот если бы Engine создавался внутри машины, тогда это Car
// Управлял бы жизненным циклом Engine
```


____________________________________________

Линия со стрелкой без ромбика - отношение осведомленности
LineShape содержит ссылку на объект Color, который может использоваться
также и другими фигурами.

LineShape знает о Color, но Color не является его частью

Связь "uses-a" (использует) - LineShape применяет Color для своей работы,
но цвет является его составной частью
Целое и часть равноправны - Color существует независимо и может использоваться
другими объектами
Нет управления жизненным циклом - LineShape не создает и не уничтожает Color.

[LineShape] → [Color]

```csharp
public class Color { } // Независимый класс

public class LineShape
{
    private Color _color; // Ассоциация: LineShape использует Color

    public LineShape(Color color)
    {
        _color = color; // Color передаётся извне
    }
}
```

## Вывод

между осведомленностью и аггрегированием с точки зрения кода нет разницы
но есть разница с точки зрения смысла:

аггрегирование (является частью) - часть может быть сразу в нескольких
целых, при этом часть - логическая часть целого и "подчиняется" целому
часть вряд ли будет участником другого бизнес процесса (Двигатель без машины
вряд ли будет полезен)

осведомленность - целое существует без части, целое и часть равны
часть может быть участником другого бизнес процесса (Учитель может без школы
быть в другом процессе)

композиция - жесткое владение, часть создается в целом и живет вместе с ним


## UML
Осведомленность — "знает о" (Student → Library).

Агрегация — "содержит часть" (Car ◇──> Engine).

Композиция — "владеет полностью" (Human ◆──> Heart).
