## Уровень 1. Нужно реально уметь (ежедневно/еженедельно)

Это то, без чего senior-бэкендер **не может работать** — он либо сам это делает, либо ревьюит, либо дебажит.

| Тема | Зачем именно тебе |
|---|---|
| **Dockerfile: кэш слоёв, порядок инструкций** | Ты пишешь и ревьюишь Dockerfile'ы своего сервиса. Плохой порядок = 10-минутные сборки в CI. |
| **Exec form + обработка SIGTERM + graceful shutdown** | Ты пишешь приложение. Если оно не умирает за 10 сек — это **твой** баг, не инфры. Rolling deploy без этого — боль. |
| **Multi-stage build** | Стандарт для любого компилируемого/интерпретируемого сервиса. Без него — 1 ГБ образы. |
| **`docker exec`, `docker logs -f`, `docker inspect`** | Твой ежедневный дебаг. |
| **`docker compose` (v2)** | Локальная разработка, интеграционные тесты, иногда — небольшие прод-стенды. |
| **Сети: bridge, user-defined bridge, DNS по имени сервиса** | «Почему api не видит db» — это ты дебажишь, а не сетевик. |
| **Volume vs bind mount** | Ты конфигурируешь compose, ты знаешь, где данные. |
| **`--memory`, `--cpus`, healthcheck** | Ты пишешь манифесты (compose / k8s values), ты обязан понимать, что ставишь. |
| **Секреты: не в образе, не в `ENV` в Dockerfile** | Это твоя ответственность как автора сервиса. Утечка секрета в образ — твой инцидент. |
| **Non-root `USER` в Dockerfile** | Одна строка, но это базовая гигиена, и на ревью спросят. |
| **`.dockerignore`** | Влияет на скорость сборки и размер контекста. |
| **Коды выхода, 137 vs 143, базовый `docker inspect`** | Ты первый, кто смотрит, почему упал **твой** сервис. |

Это ~70% того, что мы прошли. Если это не автоматизировано — ты либо сам, либо на ревью.

## Уровень 2. Нужно понимать концептуально (но не обязан делать руками)

Это то, что senior **должен знать на уровне модели**, чтобы не принимать глупых решений и не спорить с инфрой вслепую. Но конкретные команды/тулинг — не твоя ежедневная работа.

| Тема | Что достаточно знать |
|---|---|
| **Namespaces, cgroups, overlay2** | Модель: «контейнер — это процесс с изоляцией, ядро общее». Не нужно помнить флаги `clone()` или пути в `/sys/fs/cgroup`. Нужно понимать **следствия**: почему `docker stop` не «замораживает», почему БД на overlay2 — плохо, почему `--memory` важен. |
| **PID 1, tini, зомби** | Понимать, **почему** приложение должно обрабатывать SIGTERM и почему shell-form `CMD` — ловушка. `tini`/`--init` — знать, что существует, ставить по умолчанию. |
| **BuildKit cache mounts, `--cache-from`, buildx** | Знать, что это есть и что спросить у CI-команды, если сборки медленные. Самому настраивать — если в вашей команде это на тебе. |
| **Multi-arch (`linux/amd64` vs `arm64`)** | Знать, что образ собирается под архитектуру. Если у вас Mac M-серии и прод на x86 — это твоя проблема при локальной сборке. |
| **`depends_on` + healthcheck в compose** | Знать, почему `depends_on` без `condition: service_healthy` бесполезен. |
| **`docker events`, OOMKilled, базовый OOM-дебаг** | Знать, **как посмотреть** и что означает 137+OOMKilled=true. Глубокий auditd — не твой уровень. |
| **Distroless / scratch / alpine** | Знать компромиссы (размер vs отладка vs CVE). Выбор — часто твой, но не углубляйся в тонкости musl vs glibc, пока не столкнёшься. |
| **Supply chain: SBOM, cosign, trivy** | Знать, что существует и зачем. Внедрение — обычно платформа/security. |
| **Logging driver, ротация логов** | Знать, что `json-file` растёт, что есть `max-size`/`max-file`. Настройка `daemon.json` — часто инфра. |

Это ~20%. Достаточно **модели и знания, куда смотреть**, не нужно зубрить команды.

## Уровень 3. SRE / platform / security

Это то, что в зрелой компании делает **не** бэкендер. Знать, что это существует — да. Уметь — нет.

- **`auditd`, `nsenter`, sidecar-дебаг через `--pid=container`** — это SRE-инструментарий для разбора инцидентов. Ты должен знать, что «есть такой способ», и позвать человека. Сам будешь делать — если ты в маленькой команде без SRE.
- **Глубокие cgroups v1 vs v2, `/sys/fs/cgroup/...`** — платформа.
- **Настройка Docker daemon, rootless, seccomp-профили, AppArmor** — безопасность/платформа.
- **`docker stack deploy`, swarm** — легаси, забудь.
- **Внутренности containerd/runc/shim на уровне кода** — только если пишешь свой container runtime.
- **`docker attach` и его сигнальная модель** — на самом деле это **антипаттерн**, который senior должен знать, чтобы **не делать**. Знать «почему нельзя» — да. Уметь — не нужно, потому что не надо.

Это ~10%. Достаточно **слышать звон**.
