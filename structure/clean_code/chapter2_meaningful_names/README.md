1. Имена должны передавать намерения программиста

2. Избегайте дезинформации

3. Используйте осмысленные различия

Недостаточно добавить в имя серию цифр или неинформативные слова, даже 
если компилятору этого будет достаточно. Если имена различаются, то они 
должны обозначать разные понятия.

Допустим, у вас имеется класс Product. Создав другой класс с именем 
ProductInfo или ProductData, вы создаете разные имена, которые по сути обозначают одно и то же. Info и Data не несут полезной информации.

4. Используйте удобопроизносимые имена

5. Выбирайте имена, удобные для поиска 

6. Длина имени должна соответствовать размеру его области видимости 

7. Избегайте схем кодирования имен 

8. Избегайте мысленных преобразований - хранения в голове смысла переменных 

9. Старайтесь не использовать в именах классов такие слова, как Manager, Processor, Data или Info. Имя класса не должно быть глаголом. 

10. При перегрузке конструкторов используйте статические методы-фабрики с именами, описывающими аргументы. 
Например, запись
Complex fulcrumPoint = Complex.FromRealNumber(23.0);
обычно лучше записи
Complex fulcrumPoint = new Complex(23.0);


11. Выберите одно слово для каждой концепции 

12. Аналогичным образом, использование терминов controller, manager и driver в одной кодовой базе тоже вызывает путаницу 

13. Воздержитесь от каламбуров 

14. Добавьте контекста к именам переменных 
Основные трудности с выбором хороших имен обусловлены необходимостью Хороших описательных навыков и единого культурного фона. Это вопрос препо￾давания, а не вопрос техники, экономики или управления. В результате многие специалисты, работающие в этой области, так и не научились хорошо справляться с этой задачей.
