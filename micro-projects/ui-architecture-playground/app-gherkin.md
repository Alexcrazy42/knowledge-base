# Gherkin-сценарии для Jira Board (Local-First)

## 📌 Фичи (Features) и их назначение

| Фича | Назначение |
|------|-----------|
| **Board Management** | Создание/переключение/удаление досок |
| **Task Management** | CRUD для задач всех типов |
| **Drag-and-Drop** | Перемещение задач по статусам |
| **Epic Management** | Работа с эпиками (создание, связывание задач) |
| **User Management** | Управление пользователями-исполнителями |
| **Data Seeding** | Заполнение тестовыми данными |
| **Persistence** | Сохранение/восстановление из localStorage |
| **UI Navigation** | Переключение между доской и списком |

---

## 1️⃣ Фича: Board Management (Управление досками)

```gherkin
Функция: Управление досками
  Как пользователь
  Я хочу создавать и переключать доски
  Чтобы организовать работу над разными проектами

  Сценарий: Создание новой доски
    Допустим на главном экране нет досок
    Когда я нажимаю "Создать доску"
    И ввожу название "Sprint 2025-03"
    И нажимаю "Сохранить"
    Тогда появляется доска с названием "Sprint 2025-03"
    И доска содержит колонки: "To Do", "In Progress", "Done"
    И доска пуста (нет задач)

  Сценарий: Переключение между досками
    Допустим у меня есть доски "Project A" и "Project B"
    Когда я выбираю доску "Project B"
    Тогда отображается доска "Project B"
    И задачи отображаются из доски "Project B"

  Сценарий: Удаление доски
    Допустим выбрана доска "Sprint 2025-03"
    Когда я нажимаю "Удалить доску"
    И подтверждаю удаление
    Тогда доска "Sprint 2025-03" удаляется
    И отображается список оставшихся досок

  Сценарий: Переименование доски
    Допустим выбрана доска "Old Name"
    Когда я нажимаю "Редактировать название"
    И ввожу новое название "New Name"
    И нажимаю "Сохранить"
    Тогда доска переименовывается в "New Name"
```

## 2️⃣ Фича: Task Management (Управление задачами)

```gherkin
Функция: Управление задачами
  Как пользователь
  Я хочу создавать, редактировать и удалять задачи
  Чтобы планировать работу и отслеживать прогресс

  Сценарий: Создание простой задачи
    Допустим открыта доска "Sprint 2025-03"
    Когда я нажимаю "Создать задачу"
    И заполняю поля:
      | Поле         | Значение                  |
      | Заголовок    | "Рефакторинг кода"        |
      | Описание     | "Улучшить читаемость"     |
      | Исполнитель  | "Алексей"                 |
      | Статус       | "To Do"                   |
      | Тип          | "Задача"                  |
      | Приоритет    | "Высокий"                 |
    И нажимаю "Создать"
    Тогда задача появляется в колонке "To Do"
    И задача имеет уникальный идентификатор (например, "TASK-1")
    И у задачи указан текущий статус "To Do"

  Сценарий: Создание задачи с дедлайном
    Допустим открыта доска "Sprint 2025-03"
    Когда я создаю задачу с полями:
      | Заголовок    | "Завершить отчет"         |
      | Дедлайн      | "2025-09-01"              |
    Тогда у задачи отображается дедлайн

  Сценарий: Редактирование задачи
    Допустим существует задача "TASK-1" с заголовком "Рефакторинг"
    Когда я открываю карточку задачи
    И меняю заголовок на "Полный рефакторинг модуля"
    И меняю исполнителя на "Мария"
    И нажимаю "Сохранить"
    Тогда задача обновляется с новыми значениями

  Сценарий: Удаление задачи
    Допустим существует задача "TASK-1"
    Когда я открываю карточку задачи
    И нажимаю "Удалить"
    И подтверждаю удаление
    Тогда задача исчезает из доски
    И задача удаляется из всех списков

  Сценарий: Просмотр деталей задачи (клик по карточке)
    Допустим на доске есть задача "TASK-1"
    Когда я кликаю по карточке задачи
    Тогда открывается модальное окно с деталями
    И отображаются все поля задачи
    И есть кнопка "Редактировать"
    И есть кнопка "Удалить"
    И есть кнопка "Закрыть"

  Сценарий: Фильтрация задач по исполнителю
    Допустим на доске есть задачи с исполнителями "Алексей" и "Мария"
    Когда я выбираю фильтр "Только мои задачи"
    Тогда отображаются только задачи, где исполнитель совпадает с выбранным

  Сценарий: Сортировка задач по приоритету
    Допустим на доске есть задачи с разными приоритетами
    Когда я выбираю сортировку "По приоритету"
    Тогда задачи в колонках сортируются: сначала Высокий, затем Средний, затем Низкий
```

## 3️⃣ Фича: Drag-and-Drop (Перемещение задач)

```gherkin
Функция: Drag-and-Drop задач
  Как пользователь
  Я хочу перетаскивать задачи между колонками
  Чтобы обновлять статус работы визуально

  Сценарий: Перемещение задачи между колонками
    Допустим задача "TASK-1" находится в колонке "To Do"
    Когда я перетаскиваю задачу "TASK-1" в колонку "In Progress"
    Тогда задача появляется в колонке "In Progress"
    И статус задачи меняется на "In Progress"
    И задача исчезает из колонки "To Do"

  Сценарий: Перемещение задачи внутри одной колонки (смена порядка)
    Допустим в колонке "To Do" есть задачи в порядке:
      1. "TASK-1"
      2. "TASK-2"
      3. "TASK-3"
    Когда я перетаскиваю "TASK-3" на первое место
    Тогда порядок становится:
      1. "TASK-3"
      2. "TASK-1"
      3. "TASK-2"

  Сценарий: Запрет перемещения в предыдущую колонку (кастомный workflow)
    Допустим задача "TASK-1" находится в колонке "Done"
    Когда я пытаюсь перетащить её обратно в "In Progress"
    Тогда система показывает предупреждение
    И задача остаётся в "Done"
    (ПРИМЕЧАНИЕ: зависит от настроек workflow, можно сделать опциональным)

  Сценарий: Анимация при перетаскивании
    Допустим я перетаскиваю задачу
    Тогда задача становится полупрозрачной
    И потенциальные зоны дропа подсвечиваются
    И при наведении над колонкой появляется индикатор вставки
```

## 4️⃣ Фича: Epic Management (Управление эпиками)

```gherkin
Функция: Управление эпиками
  Как пользователь
  Я хочу создавать эпики и связывать с ними задачи
  Чтобы группировать задачи по крупным фичам

  Сценарий: Создание эпика
    Допустим открыта доска "Sprint 2025-03"
    Когда я нажимаю "Создать эпик"
    И заполняю поля:
      | Заголовок    | "Авторизация и регистрация" |
      | Описание     | "Реализовать вход/выход"    |
    И нажимаю "Создать"
    Тогда эпик появляется в списке эпиков
    И эпик отображается с уникальным идентификатором (например, "EPIC-1")

  Сценарий: Привязка задачи к эпику
    Допустим существует эпик "EPIC-1" ("Авторизация")
    Когда я создаю новую задачу
    И в поле "Эпик" выбираю "EPIC-1"
    Тогда задача привязывается к эпику
    И на карточке задачи отображается метка эпика

  Сценарий: Фильтрация задач по эпику
    Допустим есть задачи, привязанные к эпикам "EPIC-1" и "EPIC-2"
    Когда я выбираю фильтр "Показать задачи EPIC-1"
    Тогда отображаются только задачи, привязанные к "EPIC-1"

  Сценарий: Просмотр прогресса эпика
    Допустим у эпика "EPIC-1" есть 5 задач:
      - 2 в статусе "Done"
      - 2 в "In Progress"
      - 1 в "To Do"
    Тогда на карточке эпика отображается прогресс "2/5 (40%)"

  Сценарий: Удаление эпика (каскадное или с переносом)
    Допустим существует эпик "EPIC-1" с привязанными задачами
    Когда я удаляю эпик "EPIC-1"
    Тогда система спрашивает: "Что делать с задачами?"
    И предлагает варианты:
      - "Удалить все задачи"
      - "Отвязать задачи от эпика"
    После выбора действия задачи обрабатываются соответствующим образом
```

## 5️⃣ Фича: User Management (Управление пользователями)

```gherkin
Функция: Управление пользователями
  Как пользователь
  Я хочу добавлять и выбирать исполнителей задач
  Чтобы распределять ответственность

  Сценарий: Добавление нового пользователя
    Допустим открыта доска
    Когда я перехожу в "Управление пользователями"
    И нажимаю "Добавить пользователя"
    И ввожу имя "Анна"
    И выбираю цвет аватарки (или генерируется автоматически)
    И нажимаю "Сохранить"
    Тогда пользователь "Анна" появляется в списке доступных исполнителей

  Сценарий: Назначение исполнителя при создании задачи
    Допустим в системе есть пользователи "Алексей" и "Мария"
    Когда я создаю задачу
    И в поле "Исполнитель" выбираю "Мария"
    Тогда задача назначается на "Марию"

  Сценарий: Назначение исполнителя через drag-and-drop (опционально)
    Допустим на доске есть задача "TASK-1" без исполнителя
    Когда я перетаскиваю иконку пользователя "Анна" на карточку задачи
    Тогда исполнителем задачи становится "Анна"

  Сценарий: Удаление пользователя
    Допустим пользователь "Анна" не назначен ни на одну задачу
    Когда я удаляю пользователя "Анна"
    Тогда пользователь исчезает из списка исполнителей
    И недоступен для выбора при создании новых задач

  Сценарий: Удаление пользователя с задачами
    Допустим пользователь "Мария" назначена на 5 задач
    Когда я пытаюсь удалить "Марию"
    Тогда система предупреждает: "Пользователь назначен на 5 задач"
    И предлагает выбрать нового исполнителя для этих задач
    После выбора задачи переназначаются
```

## 6️⃣ Фича: Data Seeding (Тестовое заполнение)

```gherkin
Функция: Заполнение тестовыми данными
  Как пользователь (разработчик/тестер)
  Я хочу быстро наполнить доску тестовыми данными
  Чтобы тестировать интерфейс без ручного ввода

  Сценарий: Добавление тестового эпика
    Допустим доска пуста
    Когда я нажимаю кнопку "Добавить тестовый эпик"
    Тогда создается эпик с названием "Тестовый эпик X"
    И эпик содержит 3-5 тестовых задач в разных статусах

  Сценарий: Наполнение доски тестовыми задачами
    Допустим доска открыта
    Когда я нажимаю кнопку "Наполнить 10 тестовыми задачами"
    Тогда создается 10 задач с различными:
      - Заголовками (генерация из шаблонов)
      - Исполнителями (случайные из списка)
      - Приоритетами (случайные)
      - Статусами (распределение по колонкам)
    И задачи распределены по колонкам:
      - 40% в "To Do"
      - 30% в "In Progress"
      - 30% в "Done"

  Сценарий: Сброс всех данных
    Допустим есть доска с задачами
    Когда я нажимаю "Сбросить все данные"
    И подтверждаю действие (вводим "СБРОС" для подтверждения)
    Тогда все доски, задачи, пользователи удаляются
    И система возвращается в начальное состояние

  Сценарий: Генерация задачи с реалистичными данными
    Когда я нажимаю "Создать тестовую задачу"
    Тогда задача создается с:
      - Заголовком из базы шаблонов (например, "Настроить CI/CD")
      - Случайным описанием
      - Случайным исполнителем из списка
      - Случайным приоритетом
    И появляется в колонке "To Do"
```

## 7️⃣ Фича: Persistence (Сохранение состояния)

```gherkin
Функция: Сохранение и восстановление данных
  Как пользователь
  Я хочу, чтобы мои данные сохранялись между сессиями
  Чтобы не потерять работу при обновлении страницы

  Сценарий: Автоматическое сохранение в localStorage
    Допустим я создал задачу "TASK-1"
    Тогда данные сохраняются в localStorage браузера
    И при обновлении страницы задача "TASK-1" отображается

  Сценарий: Восстановление состояния при загрузке
    Допустим в localStorage есть сохраненные данные
    Когда я открываю приложение
    Тогда данные загружаются из localStorage
    И отображается последняя открытая доска

  Сценарий: Экспорт данных (резервная копия)
    Допустим в системе есть несколько досок с задачами
    Когда я нажимаю "Экспортировать данные"
    Тогда создается JSON-файл со всеми данными
    И файл автоматически скачивается

  Сценарий: Импорт данных
    Допустим у меня есть JSON-файл с экспортированными данными
    Когда я нажимаю "Импортировать данные"
    И выбираю файл
    Тогда данные из файла загружаются в систему
    И заменяют текущее состояние (с предупреждением)

  Сценарий: Отображение статуса сохранения
    Когда я выполняю любое действие (создание/перемещение/удаление)
    Тогда в интерфейсе появляется индикатор "Сохранено" / "Идет сохранение..."
    Чтобы я знал, что данные не потеряются при закрытии
```

## 8️⃣ Фича: UI Navigation (Навигация между доской и списком)

```gherkin
Функция: Навигация по представлениям
  Как пользователь
  Я хочу переключаться между доской и списком задач
  Чтобы выбирать удобный способ отображения

  Сценарий: Переключение на доску
    Допустим я нахожусь в списке задач
    Когда я нажимаю на вкладку "Доска"
    Тогда отображается канбан-доска с колонками
    И задачи отображаются как карточки

  Сценарий: Переключение на список задач
    Допустим я нахожусь на доске
    Когда я нажимаю на вкладку "Список"
    Тогда отображается таблица/список всех задач
    И задачи отсортированы по статусу или ID

  Сценарий: Просмотр задач в списке с дополнительной информацией
    Допустим я в режиме "Список"
    Тогда для каждой задачи отображается:
      - ID задачи
      - Заголовок
      - Статус (цветная метка)
      - Исполнитель (аватарка)
      - Приоритет (иконка)
      - Дедлайн (если есть)
      - Эпик (если привязан)
    И каждая строка кликабельна (открывает детали)

  Сценарий: Поиск задачи в списке
    Допустим я в режиме "Список"
    Когда я ввожу текст в поле поиска "рефакторинг"
    Тогда отображаются только задачи, содержащие "рефакторинг" в заголовке или описании
    И количество найденных задач отображается

  Сценарий: Текущая доска отображается в заголовке
    Когда я нахожусь на доске "Sprint 2025-03"
    Тогда в заголовке отображается "Sprint 2025-03"
    И есть переключатель между режимами "Доска" / "Список"
```

## 9️⃣ Фича: Drag-and-Drop в списке (опционально)

```gherkin
Функция: Drag-and-Drop в списке задач
  Как пользователь
  Я хочу менять порядок задач в списке перетаскиванием
  Чтобы быстро ранжировать задачи

  Сценарий: Изменение порядка задач в списке
    Допустим я в режиме "Список"
    Когда я перетаскиваю строку с задачей вверх/вниз
    Тогда порядок задач меняется
    И новый порядок сохраняется
```

## 🔟 Фича: Метаданные и автоматические поля

```gherkin
Функция: Автоматическое заполнение метаданных
  Как система
  Я хочу автоматически отслеживать время создания и изменения задач
  Чтобы у пользователя была полная история

  Сценарий: Автоматическое заполнение даты создания
    Когда создается новая задача
    Тогда поле "Создана" устанавливается на текущую дату и время
    И поле "Создана" нельзя изменить вручную

  Сценарий: Автоматическое обновление даты изменения
    Когда задача редактируется (заголовок, описание, исполнитель и т.д.)
    Тогда поле "Обновлена" устанавливается на текущую дату и время

  Сценарий: Автоматическая генерация ID задачи
    Когда создается новая задача
    Тогда ей присваивается уникальный ID в формате "TASK-N"
    Где N - инкрементальный номер для данной доски

  Сценарий: Автоматическая генерация ID эпика
    Когда создается новый эпик
    Тогда ему присваивается уникальный ID в формате "EPIC-N"
    Где N - инкрементальный номер для данной доски
```
