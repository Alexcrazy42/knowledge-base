# Tour Aggregator

Задача: Сервис обработки и ценообразования авиабилетов (Tour Pricing & Processing Service)

Сервис агрегации туров. Система получает билеты от множества внешних поставщиков

## Функциональные требования

### Базовый пайплайн

1. Обработать сырые данные от разных провайдеров (у каждого свой формат)
2. Применить правила расчета цен
3. Применить различные скидки и наценки
4. Валидировать доступность
5. Обогатить данные от себя (рейтинги и тд)
6. Сохранить результат

### Многоуровневое ценообразования

Базовая цена от провайдера проходит через pipeline:

1. Конвертация валюты (провайдеры присылают USD, EUR, RUB)
2. Агентская наценка (10-15% от базовой цены)
3. Сезонные коэффициенты (Новый год +30%, низкий сезон -20%)
4. Динамическое ценообразование (если осталось <3 мест → +15%)
5. Скидки:

- Ранее бронирование (>60 дней до вылета = -10%)
- Постоянный клиент (>3 покупок = -5%)
- Корпоративный клиент (фиксированная скидка по контракту)
- Промокоды

6. B2B наценка (если клиент — агентство, добавляется их комиссия)

#### Правила ценообразования

1. Добавление новых правил ценообразования без изменения кода
2. Комбинация правила (некоторые могут быть взаимоисключающими)
3. Вывод пользователю какие скидки применились конкретно к нему


### Валидация и бизнес правила

- Даты вылета (не в прошлом, не >365 дней вперёд)
- Количество туристов (взрослые + дети, младенцы бесплатно до 2 лет)
- Доступность перелетов (асинхронный запрос к провайдеру)
- Визовые требования (граждане РФ в Турцию без визы, в Шенген — нужна)
- Минимальная цена (не может быть <$100 за перелет — подозрение на ошибку)
- Blacklist отелей (некоторые отели забанены из-за проблем)

Требование: Валидация должна быть:

- Композитной (можно добавлять новые правила)
- Асинхронной (некоторые проверки требуют внешних вызовов)
- С понятными ошибками (клиент должен понимать, почему тур отклонён)

### Обогащение данных

После обработки нужно добавить:

- Рейтинг отеля из внешнего API (TripAdvisor, Booking.com)
- Погоду в регионе на даты поездки
- Информацию о визах
- Акции и спецпредложения отеля

Требование: Обогащение должно быть:
- Опциональным (если API недоступен — пропускаем)
- Параллельным (запросы к разным API идут одновременно)
- С fallback (если TripAdvisor не отвечает — берём из Booking)

### Workflow обработки

```
Raw → Parsed → Validated → Priced → Enriched → Published
                    ↓
                 Rejected
```

Требование: Нужна State Machine, где:

- Переходы логируются
- Можно добавлять новые состояния
- Есть compensation logic (откат, если что-то пошло не так)


### Подсказки с паттернами

Обязательные паттерны (без них не обойдёшься):
Strategy Pattern — для разных провайдеров и правил ценообразования
Chain of Responsibility / Pipeline — для многоступенчатой обработки цены
Factory / Abstract Factory — создание парсеров для провайдеров
Decorator Pattern — для добавления нового поведения в pipeline
Specification Pattern — для композитной валидации
State Machine — управление состояниями тура
Observer / Pub-Sub — для уведомлений

Дополнительные паттерны (если хочешь красиво):
Adapter Pattern — обёртки над внешними API
Circuit Breaker — защита от падений внешних сервисов
Saga Pattern — для распределённых транзакций
CQRS — разделение чтения (поиск туров) и записи (обработка)
Repository + Unit of Work — работа с данными
Null Object Pattern — для опциональных обогащений
