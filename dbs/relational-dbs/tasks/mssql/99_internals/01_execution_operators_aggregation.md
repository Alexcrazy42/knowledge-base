# Аггрегация


SQL Server имеет два принципиально разных движка для аггрегации:

1. Stream Aggregate

Sequence based (итератор, работающий с отсортированными данными)

Выбирается, когда:

- данные уже отсортированы по Group By ключу
- есть индекс с ключом Group By
- план содержит Sort перед аггрегацией

Особенности:
- Работает за O(n) после сортировки
- Использует минимум памяти: только один активный аккумулятор на группу
- Не Blocking Operator, тк Stream аггрегирует на лету
- Может работать с LOB Данными через ссылки

Пример работы:

```txt
Данные после сортировки: partnerId, amount

1, 100
1, 200  ← новая строка, та же группа → обновляем сумму
1, 150  ← обновляем сумму
2, 300  ← группа изменилась → выдаем результат для partner_id=1 (сумма=450), инициализируем новую
2, 50   ← обновляем сумму для 2
3, 500  ← выдаем для 2 (сумма=350), инициализируем 3

-- Память в любой момент времени: одна строка с аккумуляторами
```


Память: O(1) - один аккумулятор
Диск: Никогда (только если Sort не поместился в память)
Проходов: 1 после сортировки

2. Hash Aggregate

Hash-based (хеш-таблица в памяти)

Когда выбирается:
- нет порядка в выходных данных
- много уникальных групп (> 1000)
- достаточно памяти для хеш таблиц

Трехуровневая стратегия памяти Hash Aggregate:

```txt
Уровень 1: In-memory hash table
├── Грант памяти (memory grant) запрашивается до выполнения
├── Оптимизатор оценивает количество уникальных групп
└── Используется для небольших и средних данных

Уровень 2: Hash recursion (с рекурсивными хешами)
├── Когда память заканчивается, но данные еще не слишком большие
├── Создается второй уровень хеш-таблицы с другим хеш-алгоритмом
└── Может быть до 7 уровней рекурсии

Уровень 3: Spill to tempdb (аварийный режим)
├── Все данные пишутся на диск в tempdb
├── Каждый спилл-файл содержит частично агрегированные данные
├── На финальной фазе читаются и доагрегируются
└── ОЧЕНЬ МЕДЛЕННО (в 100-1000 раз медленнее памяти)
```

Пример работы:

```txt
-- Память: хеш-таблица с 8 бакетами (для 5 групп)
-- Бакет 0: [key=1, sum=1000] → [key=9, sum=500] (коллизия)
-- Бакет 1: [key=2, sum=300]
-- Бакет 2: [key=3, sum=700]
-- Бакет 3: пусто
-- ...

-- Каждая новая строка:
-- 1. Хешируем partner_id
-- 2. Находим бакет
-- 3. Если ключ найден → обновляем сумму
-- 4. Если не найден → создаем новый узел
```

Память: O(num_groups) - хеш-таблица групп
Диск: Может спиллить на диск (рекурсивно)
Проходов: 1 (если в памяти) или 2+ (если спилл)

3. Window Aggregate

Spool-based (материализация окон с возможностью навигации)

Трехфазная модель выполнения: сортировка данных по PARTITION BY, ORDER BY; Материализация окна в Window Spool; Вычисление оконных функций для каждой строки


Память: O(partition_size) - ВСЯ партиция
Диск: Почти всегда (Window Spool в tempdb на больших партициях)
Проходов: 
  - 1 проход на сортировку
  - 1 проход на спул
  - 1 проход на вычисления
  - + обращение к спулу для каждой строки (фреймы)



Полный пример выполнения:

1. Запросы

```sql
SELECT 
    partner_id,
    claim_date,
    amount,
    ROW_NUMBER() OVER (PARTITION BY partner_id ORDER BY claim_date) as rn,
    SUM(amount) OVER (PARTITION BY partner_id 
                      ORDER BY claim_date
                      ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) as running_sum
FROM claims;
```

Шаг 1. Исходные данные (100_000 строк)

```txt
partner_id, claim_date, amount
1, 2024-01-10, 100
2, 2024-01-15, 500
1, 2024-01-20, 300
2, 2024-01-05, 200
... (еще 99,996 строк)
```

Шаг 2. Сортировка (фаза 1)

```txt
Оператор: Sort
Память: 500 MB memory grant
Tempdb: 2 GB (спилл, так как 100k строк * 200 байт = 20 MB вроде бы, 
                но с учетом сортировки и промежуточных структур)

Результат в memory/tempdb:
[1, 2024-01-10, 100]
[1, 2024-01-20, 300]
[2, 2024-01-05, 200]
[2, 2024-01-15, 500]
...
```

Шаг 3. Создание Window Spool (фаза 2)

```txt
Оператор: Segment + Window Spool
Память: 200 MB (для хранения текущей партиции)
Tempdb: 3 GB (если партиции большие)

В Window Spool:
Partition 1: [row0, row1, row2, ... row1500]  ← partner1 имеет 1500 строк
Partition 2: [row0, row1, row2, ... row2300]  ← partner2 имеет 2300 строк
...
```

Шаг 4. Вычисление для каждой строки (фаза 3)

```txt
Для каждой строки в Window Spool (последовательно):

Строка 0 (partner=1, pos=0):
  - rn = 0 + 1 = 1
  - running_sum = amount[0..0] = 100
  Выдаем: [1, 2024-01-10, 100, 1, 100]

Строка 1 (partner=1, pos=1):
  - rn = 1 + 1 = 2
  - running_sum = amount[0..1] = 100 + 300 = 400
  Выдаем: [1, 2024-01-20, 300, 2, 400]

Строка 2 (partner=2, pos=0):
  - rn = 0 + 1 = 1
  - running_sum = amount[0..0] = 200
  Выдаем: [2, 2024-01-05, 200, 1, 200]

... и так для всех 100,000 строк
```
