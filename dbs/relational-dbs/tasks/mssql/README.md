# MS SQL

У MS SQL очень интересная логика для транзакций

```sql
  CREATE OR ALTER PROCEDURE Test_Exception
  AS
  BEGIN
  SET XACT_ABORT ON;
  BEGIN TRANSACTION;
    UPDATE Boards SET name = 'Тест1'

	SELECT 1 / 0;

	UPDATE Boards SET name = 'Тест2'
	COMMIT TRANSACTION;
  END;
```

Только в такой конфигурации не будет заменено значение ни на Тест1, ни на Тест2

Если убрать SET XACT_ABORT ON, то после обновлений будет Тест2, тк эта настройка указывает, что нужно автоматически откатить текущую транзакцию, если возникала ошибка.

Если убрать транзакцию, то значение будет Тест1, тк мы не указали транзакцию, а в SQL Server по умолчанию каждая отдельная инструкция выполняется в своей собственной транзакции. Поэтому первая неявная транзакция выполняется, а после XACT_ABORT срабатывает, прерывает выполнение пакета, но откатывать ему нечего, так как предудыщий UPDATe уже завершился и зафиксировался

Если же не будет ни того, ни другого, то значение после будет - Тест2
