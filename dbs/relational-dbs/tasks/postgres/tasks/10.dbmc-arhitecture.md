# Глава 10. Архитектура СУБД

Не буду супер глубоко углубляться, просто на уровне ознакомления
Логика, связанная с серверной частью postgres находится в src/backend.

## 10.1

Найдите в исходном коде PostgreSQL модули, отвечающие за:

1. управление сеансами

src/backend/access/session.c 

Этот модуль управляет данными, которые относятся к одному пользовательскому подключению (сеансу), например, для работы параллельных запросов. CurrentSession — это важная глобальная переменная.

2. разграничение доступа

src/backend/catalog/aclchk.c (Access Control List)

Здесь происходит проверка прав доступа к объектам базы данных (таблицам, схемам, функциям). Название "ACL" расшифровывается как Access Control List (список контроля доступа).

3. диспетчеризацию транзакций

src/backend/access/transam/xact.c (Transaction Manager)

Это "мозг" транзакций. Отвечает за команды BEGIN, COMMIT, ROLLBACK и управляет состояниями транзакций. transam означает Trans**action Manager.

4. ведение журнала транзакций

src/backend/access/transam/xlog.c (Transaction Manager)

XLog — это и есть журнал предзаписи (Write-Ahead Log). Этот файл — один из самых важных для надежности: он гарантирует, что данные не потеряются при сбое.

5. рестарт сервера базы данных

src/backend/postmaster/postmaster.c

Это главный управляющий процесс. Он запускает ("форкает") все остальные служебные процессы (например, процесс восстановления) и перезапускает их в случае сбоя, обеспечивая "рестарт" всего кластера.

6. выполнение операций реляционной алгебры

src/backend/executor/execMain.c

execMain.c, nodeSeqscan.c, nodeJoin.c и др
Executor (исполнитель) берет готовый план запроса от оптимизатора и выполняет его. Он реализует такие операции, как sequential scan (последовательное сканирование), join (соединение), filter (фильтрация).


7. реализацию основных структур хранения данных

src/backend/access/heap/heapam.c

Heap — это основная структура для хранения самих строк (кортежей) данных. Файлы в папке heap управляют чтением, записью и удалением этих строк на диске.

8. оптимизацию запросов

src/backend/optimizer/plan/planner.c

Optimizer (оптимизатор) получает SQL-запрос, разбирает его, перебирает возможные способы выполнения ("пути" или path), оценивает их стоимость и выбирает самый эффективный план.

9. реализацию и использование индексов на основе B-деревьев

src/backend/access/nbtree/nbtree.c

nbtree — это реализация классического B-дерева, самого популярного типа индекса в PostgreSQL (создается по умолчанию).

10. реализацию индексов Gist

src/backend/access/gist/gist.c

GiST (Generalized Search Tree) — это не конкретный индекс, а фреймворк для построения разных индексов (например, для полнотекстового поиска или географических данных)
