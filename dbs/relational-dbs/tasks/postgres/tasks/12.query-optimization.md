# 12.2

В базе данных постройте индексы для поиска вариантов перелета по названию пунктов отправления и прибытия и дате вылета

```sql
SELECT * 
FROM routes r
JOIN flights f on f.route_no = r.route_no
WHERE scheduled_departure >= '2025-12-21'
  AND scheduled_departure < '2025-12-22'
AND r.departure_airport = 'LED'
and r.arrival_airport = 'OVB'
LIMIT 5
```

План:

```text
Limit  (cost=4.72..37.49 rows=1 width=154) (actual time=0.150..0.199 rows=2 loops=1)
  ->  Nested Loop  (cost=4.72..37.49 rows=1 width=154) (actual time=0.148..0.196 rows=2 loops=1)
        ->  Bitmap Heap Scan on routes r  (cost=4.44..29.17 rows=1 width=103) (actual time=0.074..0.104 rows=2 loops=1)
              Recheck Cond: (departure_airport = 'LED'::bpchar)
              Filter: (arrival_airport = 'OVB'::bpchar)
              Rows Removed by Filter: 19
              Heap Blocks: exact=11
              ->  Bitmap Index Scan on routes_departure_airport_lower_idx  (cost=0.00..4.43 rows=21 width=0) (actual time=0.053..0.053 rows=21 loops=1)
                    Index Cond: (departure_airport = 'LED'::bpchar)
        ->  Index Scan using flights_route_no_scheduled_departure_key on flights f  (cost=0.29..8.31 rows=1 width=51) (actual time=0.040..0.041 rows=1 loops=2)
              Index Cond: ((route_no = r.route_no) AND (scheduled_departure >= '2025-12-21 00:00:00+00'::timestamp with time zone) AND (scheduled_departure < '2025-12-22 00:00:00+00'::timestamp with time zone))
Planning Time: 1.261 ms
Execution Time: 0.257 ms
```

Сейчас мы ищем по индексу routes_departure_airport_lower_idx, что не очень эффективно, тк нас интересуют и аэропорт вылета и прилета

Создадим индекс:

```sql
create index if not exists routes_departure_and_arrival
    on bookings.routes (departure_airport, arrival_airport);

ANALYZE routes
```

Новый план

```text
Limit  (cost=0.56..16.62 rows=1 width=154) (actual time=0.101..0.114 rows=2 loops=1)
  ->  Nested Loop  (cost=0.56..16.62 rows=1 width=154) (actual time=0.100..0.112 rows=2 loops=1)
        ->  Index Scan using routes_departure_and_arrival on routes r  (cost=0.28..8.30 rows=1 width=103) (actual time=0.056..0.058 rows=2 loops=1)
              Index Cond: ((departure_airport = 'LED'::bpchar) AND (arrival_airport = 'OVB'::bpchar))
        ->  Index Scan using flights_route_no_scheduled_departure_key on flights f  (cost=0.29..8.31 rows=1 width=51) (actual time=0.022..0.023 rows=1 loops=2)
              Index Cond: ((route_no = r.route_no) AND (scheduled_departure >= '2025-12-21 00:00:00+00'::timestamp with time zone) AND (scheduled_departure < '2025-12-22 00:00:00+00'::timestamp with time zone))
Planning Time: 1.045 ms
Execution Time: 0.147 ms
```

связка Bitmap Heap scan + bitmap index scan по routes_departure_airport_lower_idx заменилась на index scan по новосозданному routes_departure_and_arrival

Изучите и сравните оценки стоимость для различных порядков операций соединения каждого запроса

```sql
SET join_collapse_limit = 1;
SET from_collapse_limit = 1;

EXPLAIN ANALYZE
    SELECT
    bp.seat_no, t.passenger_name, f.scheduled_departure, f.scheduled_arrival,
    r.departure_airport, r.arrival_airport
FROM boarding_passes bp
JOIN tickets t on bp.ticket_no = t.ticket_no
JOIN flights f on bp.flight_id = f.flight_id
JOIN routes r on f.route_no = r.route_no
WHERE f.status NOT IN ('Arrived', 'Cancelled', 'Departed')
```
